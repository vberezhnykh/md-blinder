# MD Blinder

Браузерное приложение для конвертации документов в Markdown и обезличивания. Конвертация, OCR и распознавание сущностей выполняются локально, без отправки текста документов на сервер.

## Возможности

- DOCX → Markdown с таблицами и списками; PDF с текстовым слоем и сканы через OCR на русском, украинском и английском.
- Автоматический выбор OCR для сканов и смешанных страниц. Для сложного PDF можно включить «Распознать все страницы следующего PDF через OCR» перед загрузкой.
- Многоязычный NER GLiNER и структурные правила для телефонов, email, банковских реквизитов и других данных.
- Ручная разметка, объединение сущностей, поиск повторов, принятие/отклонение кандидатов; undo/redo сохраняет и текст, и разметку.
- Предпросмотр, копирование, экспорт Markdown и таблицы замен CSV. Перед скачиванием Markdown запускается контрольная проверка актуальной версии документа.
- Локальная история, автосохранение, импорт/экспорт истории JSON, отмена длительной обработки.

Если текст или разметка изменились во время контрольной проверки, экспорт нужно запустить заново. Недоступность NER обозначается как неполная проверка; скачивание требует явного подтверждения. Копирование быстрее: контрольный проход перед ним не выполняется.

## Приватность и ограничения

История IndexedDB содержит **исходный текст и значения сущностей без шифрования**. Экспорт истории JSON и таблица замен CSV тоже содержат исходные данные — это не обезличенные файлы. Не передавайте их вместе с результатом. Для удаления сохранённого документа используйте историю; очистка данных сайта удалит также локальный кеш моделей.

Изображения могут содержать подписи, печати и персональные данные, которые текстовая разметка не закрывает. Поэтому в обезличенном предпросмотре, буфере и Markdown изображения и их встроенные данные заменяются отметкой об удалении. Исходник в редакторе/истории сохраняется. Отдельного обезличивания картинок нет.

Первое распознавание скачивает около **580 МБ** fp16-модели NER плюс токенизатор; для OCR дополнительно нужны движок и языковые модели. Запросы идут к Hugging Face и jsDelivr за публичными ресурсами, не за обработкой ваших документов. NER-модель и токенизатор закреплены на одной ревизии; ONNX JS/WASM поставляются вместе со сборкой. Кеш браузера может быть очищен или недоступен, поэтому offline-работа после первого запуска не гарантируется.

Рекомендуется актуальный настольный Chromium/Chrome/Edge, HTTPS или localhost, достаточная память и свободное место. WebGPU используется при доступном адаптере и успешной многоязычной самопроверке; иначе включается более медленный WASM/CPU. Самопроверка выявляет грубые несовместимости, но не гарантирует качество распознавания любого текста. На больших документах CPU-обработка может занимать минуты. Автоматические браузерные регрессии выполняются в Chromium; Safari, Firefox и мобильные устройства отдельно не сертифицированы.

OCR и NER могут ошибаться. Проверьте сохранность таблиц/чисел и все чувствительные данные перед передачей результата. Контрольный проход уменьшает риск пропуска, но не гарантирует полной анонимности.

Автосохранение объединяет правки в течение 800 мс и дожидается записи перед переходами. При ошибке хранилища показывается повтор сохранения; не закрывайте вкладку с несохранёнными изменениями. Аварийное завершение браузера/системы всё равно может прервать незавершённую запись.

## Разработка

Node.js 24 LTS (`.nvmrc`), npm 11.19.0. Node 26 также допускается для локальной разработки. CI и Netlify используют Node 24.

```bash
npm ci
npm run dev
```

Не заменяйте `npm ci` на `npm install` в CI: lock-файл является частью воспроизводимой сборки и содержит платформенные optional-зависимости для Windows/Linux.

## Сборка

```bash
npm run build
```

Собранные файлы в `dist/` можно развернуть на любом статическом хостинге (GitHub Pages, Cloudflare Pages, Netlify).

На хостинге нужны корректные MIME-типы для `.mjs` и `.wasm`. `netlify.toml` содержит CSP и защитные заголовки; для другого хостинга перенесите их отдельно. `file://` не является поддерживаемым способом запуска.

## Проверки

```bash
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:perf
npm audit
```

`test:e2e` самостоятельно собирает приложение и запускает preview на порту 4173. Это синтетические проверки настоящего редактора, IndexedDB, структурного Worker и скачивания; только ответы тяжёлого NER управляются тестом для воспроизведения гонок. Они не измеряют качество модели.

`test:perf` — локальный микробенчмарк структурного поиска и экспорта, без модели и реальных документов. Он не заменяет измерение времени OCR/NER на целевом устройстве.

Совместимость ML-движка и команды отдельного настоящего NER-бенчмарка описаны в [docs/NER-RUNTIME.md](./docs/NER-RUNTIME.md). Он использует только синтетические примеры; первая загрузка модели включается явно через `--download`.

CI проверяет `npm ci`, lint, unit-тесты и production build на Windows/Linux, а также Chromium E2E и dependency audit на Linux. Конфиденциальный локальный корпус `test-samples/`, результаты распознавания и тестовые артефакты с реальными данными не коммитятся и не загружаются в CI. Для локальной оценки модели служат `scripts/e2e-detect.mjs` и `scripts/score.mjs`; entity score и покрытие всех вхождений — разные показатели.
