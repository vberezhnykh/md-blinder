# План переноса редизайна экрана документа

Макет: https://claude.ai/artifact/ADMGDTPhAvKU4EJiBnp4nE (приватный, открывается владельцем).

План делит перенос на восемь этапов. Каждый этап можно выпустить отдельным PR: после любого из них приложение работает целиком, а lint, unit-тесты, сборка и e2e проходят. Первые этапы почти не меняют раскладку. Самый крупный этап, «результат рядом с исходником», стоит ближе к концу, когда новые компоненты уже на месте.

Размеры этапов указаны относительно друг друга: S — правка в одном-двух файлах, M — новый компонент или изменение модели данных, L — перестройка раскладки экрана.

## Решения, которые нужно подтвердить до начала

1. **Принятый родственный кандидат получает метку исходной сущности.** Сейчас `acceptCandidate` (`src/lib/anonymize/apply.ts:215`) выдает принятому кандидату новую метку: «Иванов П. С.» становится `[PERSON_3]`, хотя это тот же человек, что и `[PERSON_1]`. В макете кандидат с причиной «Похоже на [PERSON_1]» после принятия сливается с `[PERSON_1]`. Предлагаю принять это поведение для кандидатов из `findRelatedOccurrences`. Кандидаты с низкой уверенностью модели по-прежнему получают новую метку. Если пользователь сменил тип кандидата перед принятием, слияния тоже не будет.
2. **Шрифты IBM Plex хранятся вместе со сборкой.** CSP в `netlify.toml` разрешает шрифты только из `'self'` и `data:`, поэтому Google Fonts заблокированы. Подключать сторонний сервер шрифтов к приложению, которое обещает ничего никуда не отправлять, тоже не стоит. Вариант: пакеты `@fontsource/ibm-plex-sans`, `-serif`, `-mono` с кириллицей и латиницей, только нужные начертания (400, 500, 600 для Sans; 400 и 600 для Serif; 400 и 500 для Mono). Сборка вырастет на несколько сотен килобайт woff2. Альтернатива — оставить системные шрифты и взять из макета только раскладку.
3. **Таблица замен уходит со страницы.** Раскрывающаяся «Таблица замен» под редактором повторяет список найденных данных. В макете CSV скачивается только из меню выдачи, с предупреждением об исходных данных. `ReplacementTable.tsx` удаляется.
4. **Темная тема рисуется заново.** В макете ее нет. Новые токены (плашка замены, кандидат, статус) нужно подобрать для темной темы на этапе 1, а проверить на этапе 8.

## Этап 0. Цвета для `ID_DOC` и `URL` (S)

Ошибка, которую стоит исправить отдельно и сразу. В `src/App.css` для `ID_DOC` и `URL` нет переменных `--ent-*` и классов `.cm-entity-*`. Номер паспорта не подсвечивается в редакторе, а заголовок группы и цветная метка остаются бесцветными.

- `src/App.css`: добавить `--ent-ID_DOC` и `--ent-URL` в светлую и темную тему и классы `.cm-entity-ID_DOC`, `.cm-entity-URL`.
- Новый unit-тест: для каждого типа из `ALL_ENTITY_TYPES` в `App.css` есть `--ent-<тип>` в обеих темах и класс `.cm-entity-<тип>`. Тогда новый тип нельзя будет добавить без цвета.

## Этап 1. Токены и шрифты (S)

- `package.json`: пакеты `@fontsource/*` (если решение 2 принято), импорт нужных начертаний в `src/main.tsx`.
- `src/index.css`: `--font-sans`, `--font-serif`, `--font-mono` на IBM Plex с системными запасными шрифтами. Новые токены: `--redact-bg` и `--redact-ink` для плашки замены, `--pending`, `--pending-wash`, `--pending-line` для кандидатов, `--ready` и `--ready-wash` для статуса «Готово к выдаче». Значения задаются для обеих тем.
- Существующие компоненты пока не меняются, только переходят на новые шрифтовые токены. Это отдельный коммит, чтобы при регрессии было видно, что изменились только шрифты.

## Этап 2. Меню и верхняя панель (M)

Нужен один примитив выпадающего меню, на нем строятся три меню из макета.

- Новый `src/components/Menu.tsx`: кнопка с `aria-expanded` и `aria-haspopup`, всплывающий список, закрытие по Escape, клику вне меню и выбору пункта, возврат фокуса на кнопку. Позиционирование через `position: absolute` относительно обертки, без библиотек.
- Новый `src/components/TopBar.tsx` вместо `.compact-bar` в `App.tsx`: название, имя файла, статус сохранения со значком, меню «Новый файл» и меню «История».
  - В меню «Новый файл» входят выбор файла и флажок OCR (`forceOcr`) с пояснением. Флажок исчезает из панели.
  - В меню «История» входят последние документы, открытие через существующий `handleOpenDoc`, предупреждение о хранении без шифрования, экспорт и импорт истории. Пункт «Все документы» ведет на стартовый экран, где остается полный `HistoryPanel` с удалением и отменой удаления.
  - Перетаскивание файла на панель (`handleDrop`) сохраняется.
- e2e: хелпер `history()` ищет кнопку «История», тест «importing a newer revision…» читает имя файла из `.filename-compact`, тест наведения уводит мышь на `.compact-bar`. Их нужно обновить под новую панель и меню.

## Этап 3. Строка статуса и меню выдачи (M)

- Новый `src/components/StatusStrip.tsx` между верхней панелью и рабочей областью:
  - шаги «Загрузка → Проверка → Выдача». На экране документа загрузка всегда завершена, «Проверка» активна, пока есть непроверенные кандидаты (`unreviewedCount > 0`), затем активна «Выдача»;
  - плашка «Не проверено: N кандидатов» (кнопка, открывает вкладку проверки) или «Готово к выдаче»;
  - строка «Заменено N значений в M местах»: число сущностей с `anonymize` и сумма их `positions.length`;
  - кнопка «Экспортировать .md» с меню: «Копировать текст», «Экспортировать .md», «Таблица замен (.csv)» с предупреждением.
- `App.tsx`: убрать `.result-toolbar` с кнопками действий и `details.replacement-section`, удалить `ReplacementTable.tsx` и его стили (решение 3). `handleCopy`, `handleExport`, `handleExportCsv` и `notifyDone` переносятся без изменений поведения.
- e2e: тест «export and copy use the current anonymization immediately…» находит «Копировать текст» по роли кнопки. Внутри меню это будет `menuitem`, тест нужно поправить. Новый тест: CSV скачивается из меню выдачи, плашка меняется на «Готово к выдаче» после принятия последнего кандидата.

## Этап 4. Связь кандидата с исходной сущностью (M)

Подготовка данных для очереди проверки. Видимых изменений интерфейса почти нет.

- `src/lib/anonymize/types.ts`: необязательное поле `relatedTo?: string`, id сущности, на которую похож кандидат.
- `src/lib/anonymize/relatedOccurrences.ts`: заполнять `relatedTo` id исходной сущности (`src.id`). Строку «Похоже на [PERSON_1]» больше не хранить готовой в `candidateNote`: после `compactPlaceholderNumbers` метка в ней может устареть. Причина вычисляется при показе по `relatedTo`, а `candidateNote` остается запасным вариантом для старых документов.
- `src/lib/history.ts` (около строки 180): сохранять и проверять `relatedTo` при импорте и чтении истории.
- `src/lib/anonymize/apply.ts`:
  - `acceptRelatedCandidate(entities, id)`: если `relatedTo` указывает на существующую сущность того же типа, снять с кандидата флаги и слить его с ней через `mergeEntities`, иначе вызвать прежний `acceptCandidate` (решение 1);
  - `acceptAllRelated(entities, targetId)`: принять всех непроверенных кандидатов, связанных с `targetId`;
  - `restoreCandidate(entities, id)`: вернуть отклоненного кандидата (`dismissed: false, candidate: true`).
- Unit-тесты на все три функции, на сохранение `relatedTo` в истории, на документ без `relatedTo` из старой истории и на устаревшую метку в причине после удаления сущности.
- Принятие из панели уже попадает в историю правок редактора (`entitySyncTransaction`), поэтому Ctrl+Z отменяет его вместе со слиянием. Это нужно подтвердить e2e-тестом.

## Этап 5. Очередь проверки кандидатов (M)

- Новый `src/components/CandidateReview.tsx` вместо секции `.candidates-section` в `EntityList.tsx`:
  - карточка текущего кандидата: «Кандидат K из N», переход к соседнему кандидату, значение, фрагмент текста вокруг первого вхождения (около 60 символов с каждой стороны, с обрезкой по границе слова через `src/lib/wordSnap.ts`), причина, выбор типа, «Принять», «Отклонить»;
  - «Принять все похожие на [X] (N)», если у текущего кандидата больше одного непроверенного «соседа» с тем же `relatedTo`;
  - список всех кандидатов: непроверенные с кнопкой «Открыть», отклоненные (`dismissed`) в свернутом блоке с кнопкой «Вернуть»;
  - когда кандидатов нет, показывается итог «Все кандидаты разобраны» и кнопка экспорта.
- Клавиатура: Enter принимает, Backspace отклоняет, стрелки вверх и вниз переходят к соседнему кандидату. Обработчик стоит на карточке, а не на `window`, иначе он перехватит Enter и Backspace в редакторе. После решения фокус остается на карточке, чтобы можно было разбирать кандидатов подряд.
- Текущий кандидат подсвечивается в редакторе: новый проп `activeCandidateId` в `EntityEditor.tsx` и класс `cm-entity-current` (обводка акцентным цветом). Редактор прокручивается к кандидату через существующий механизм `reveal`.
- Боковая панель получает вкладки «Проверка» и «Найденные данные». По умолчанию открыта «Проверка», если есть кандидаты. `showCandidates` в `App.tsx` переключает вкладку вместо прокрутки к `#candidates`.
- e2e: тест экспорта принимает кандидата через `.candidate-row` и `title="Принять"`, его нужно перевести на новую карточку. Новый тест: принять, перейти к следующему, принять всех похожих, отклонить и вернуть, отменить принятие через Ctrl+Z.

## Этап 6. Список найденных данных (M)

- `src/components/EntityList.tsx`:
  - заголовок группы: флажок группы, цветная точка, код типа и счетчик на нейтральном фоне вместо залитой цветом полосы;
  - флажок «Заменять» остается в начале каждой строки: это основное действие со значением, и тест группировки проверяет флажки строк;
  - значение — настоящая `<button>`. Сейчас это `span` с `role="button"`. Кнопка содержит значение, метку замены и число вхождений;
  - по клику строка выбирается: текст прокручивается к вхождению (существующий `onSelect` и `reveal`), а под строкой появляются действия «Тип», «Объединить…» и «Удалить». Сейчас они видны в каждой строке постоянно;
  - подсветка строки при наведении на сущность в редакторе (`highlightedId`) и подгонка высоты прилипающей панели остаются.
- e2e: тесты «hovering an entity…» и «found entities are grouped by type…» опираются на `.entity-row`, `.entity-group`, `.entity-group-header`, `.entity-group-name`, `.entity-group-toggle` и флажки строк. Эти классы стоит сохранить. Тест наведения уводит мышь на `.compact-bar`, после этапа 2 он должен использовать новую верхнюю панель.

## Этап 7. Результат рядом с исходником (L)

- `App.tsx` и `App.css`: рабочая область из трех колонок: редактор, результат, боковая панель. При ширине окна меньше примерно 1280 px режим «рядом» выключается сам, и над текстом появляется переключатель «Исходник / Результат» вместо нынешнего «Редактор / Анонимизированный». Выбор «Результат рядом» запоминается в `localStorage` как личная настройка; чтение и запись обернуты в try/catch.
- `src/components/AnonymizedPreview.tsx`: вместо `<pre>` блок с тем же текстом. Метки замены рисуются плашками (`mark.anon-replaced` с токенами `--redact-*`), оставшийся без замены текст выделяется волнистым подчеркиванием. `textContent` по-прежнему посимвольно совпадает с копируемым текстом, на это опираются e2e-тесты.
- Шрифт: проза в редакторе и результате набирается `--font-serif`. Строки таблиц Markdown (начинаются с `|`) остаются моноширинными: в CodeMirror это декорация строки, в результате — разбиение по строкам.
- Прокрутка: в первой версии при выборе сущности или кандидата обе колонки прокручиваются к нему. Синхронную прокрутку по смещениям через `anonymized.segments` можно добавить позже, если без нее будет неудобно.
- e2e: пять мест нажимают кнопку «Анонимизированный». Их нужно перевести на общий хелпер, который в режиме «рядом» ничего не нажимает, а в узком окне выбирает «Результат». Новый тест: переключение режима и его сохранение после перезагрузки.

## Этап 8. Темная тема, стартовый экран, документация (M)

- Проверка всех новых элементов в темной теме, подбор значений токенов из этапа 1.
- Стартовый экран (в макете его нет, поэтому изменения минимальные): заметная плашка о том, что документы не покидают браузер, предупреждение о загрузке модели около 580 МБ при первом запуске, флажок OCR внутри зоны загрузки, предупреждение о хранении истории без шифрования.
- Скриншоты в светлой и темной теме при ширине 1440 и 820 px, как в `AUDIT-UI-2026-10-06.md`, и сравнение с макетом.
- `README.md`: очередь проверки, слияние принятых родственных кандидатов, меню выдачи, перенос CSV в меню.

## Проверки на каждом этапе

```bash
npm run lint
npm test
npm run build
npm run test:e2e
```

Перед этапами 2, 3, 5, 6 и 7 нужно сначала поправить затронутые e2e-тесты, а потом менять интерфейс: так видно, что тест ловит именно новое поведение. Тесты, связанные с хранением данных (отложенное удаление, миграция IndexedDB, сброс правок при смене документа, удаление картинок из результата), не должны меняться по смыслу. Если такой тест падает, это регрессия, а не устаревший тест.

## Риски

- **Три колонки при 1440 px.** На каждый текст остается около 480 px. Если договор с широкими таблицами будет читаться плохо, боковую панель можно сделать сворачиваемой.
- **Клавиши в карточке проверки.** Обработчик срабатывает, только когда фокус на самой карточке или ее кнопках. Внутри `<select>` стрелки и Enter должны работать как обычно, а не принимать кандидата.
- **Слияние при принятии.** Слитый кандидат исчезает из списка как отдельная сущность. Отменить слияние можно только через Ctrl+Z, кнопки «Вернуть» для принятых кандидатов нет. Если это окажется неудобно, понадобится журнал решений текущей сессии.
- **Размер сборки.** Шрифты увеличат объем первой загрузки. На фоне модели NER это мало, но для страницы, которая открывается до загрузки модели, разница заметна.
